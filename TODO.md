# HireSwift delivery checklist

- [ ] **Responsive HireSwift product shell and public entry.** Build a professional responsive HireSwift interface with clear branding, desktop sidebar and mobile navigation. The app should include landing/entry, login/registration setup guidance, recruiter dashboard, resume management, job management, candidate ranking, comparison, hiring pipeline, analytics/reports, and settings/profile views. Provide a clearly labeled demo mode for exploration without registration and ensure navigation and controls have meaningful behavior, loading/error/empty states, validation and confirmations.
- [ ] **Demo workspace and sample records.** Provide at least 15 clearly labeled fictional demo candidates and at least 5 labeled demo jobs with varied skills, education, CGPA, experience, graduation years, locations and hiring stages. Include a load/reset demo data action. Make demo workflows usable before any actual resume is uploaded. Never present sample records or fixture match scores as extracted real resume information.
- [ ] **Recruiter dashboard and live summaries.** Show Total Candidates, Total Job Openings, Shortlisted Candidates, Interviews Scheduled, Offers Released and Rejected Candidates; application statistics; current hiring-pipeline visualization; recent applicants, top-ranked candidates, recent activities and job-wise recruitment statistics. Charts and summary values must derive from current workspace records and update after candidate/job changes and stage transitions.
- [ ] **Resume upload, extraction and review.** Support multi-file PDF and DOCX upload with format/size validation, per-file progress/status and success/failure feedback, duplicate detection by email/phone, and manual review when extraction is incomplete. Extract only information actually present: full name, email, phone, location, education, 10th/12th percentage, CGPA, graduation year, technical skills, programming languages, technologies, projects, work experience/years, and certifications. Do not fabricate missing fields; permit recruiter edits. Keep private resume storage documented/configurable and do not imply it is active absent credentials.
- [ ] **Job description management.** Allow recruiters to create, view, edit, delete or close job openings with title, company, description, required/preferred skills, minimum experience, education requirements, minimum CGPA, location, employment type and status. Persist in active data adapter and document external database setup.
- [ ] **Transparent job matching and skill insights.** Compute a 0–100 resume-to-job score from actual candidate/job fields with weights: Required Skills 40%, Education 15%, Work Experience 20%, Relevant Projects 10%, Certifications 5%, Additional Skills 10%. Show matching and missing skills, relevant experience, education match, strengths, gaps, explanation and recommendation. Identify the engine as deterministic rule-based matching, not a trained AI model. Keep matching modular for a future AI provider.
- [ ] **Combined candidate search, filters and ranking.** Implement combined filters for 10th percentage, 12th percentage, CGPA, technical skills, programming languages, technologies, years of experience, location, graduation year, education, job role, match percentage and recruitment status. Search candidate name, email and skills; sort by match and experience; reset filters. Filters operate on current candidate records. Candidate ranking shows descending selected-job match score, profile, skills, experience, education and status.
- [ ] **Candidate comparison.** Allow selection of at least two candidates and compare technical skills, education, CGPA, experience, projects, certifications, match scores and missing skills, with strengths/differences clearly highlighted.
- [ ] **Hiring pipeline and recruiter notes.** Provide Applied → Shortlisted → Interview → Offer / Rejected stages; display candidates by stage and allow moving candidates between stages. Track interview date/notes and recruiter feedback, rejection reasons and offer status. Persist transitions through the available active data adapter; provide usable mouse/touch controls in addition to any drag-and-drop interaction.
- [ ] **Analytics and CSV reporting.** Show total applications, shortlisting rate, interview conversion rate, offer rate, rejection rate, average match score, job-wise applications, skill distribution and hiring funnel with interactive charts. Export a recruitment report as CSV from current data.
- [ ] **Duplicate handling and bulk-email honesty.** Prevent duplicate candidate profiles and notify the recruiter of email/phone duplicates. Permit selecting shortlisted candidates and composing a bulk message in demo mode, but clearly save/report it as a draft only and never claim an email was sent absent a configured provider and confirmed send result.
- [ ] **Supabase integration and secure data model.** Include PostgreSQL migrations/schema and RLS ownership policies for users/profiles, candidates, resumes, jobs, candidate skills, applications, interviews, recruitment activities and email logs, plus a private resume bucket policy. Include optional Supabase Authentication/browser integration scaffolding using public URL/anon key only, keep service-role secrets server-side, and provide `.env.example` without credentials. Demo fallback may use browser-local storage and must identify that storage as local demo data. No external Supabase persistence is claimed until configured and migrated.
- [ ] **Express REST API and document parser.** Implement Express health/config and validated PDF/DOCX parsing endpoints, size/type restrictions, structured extraction from source text only, safe errors, and no temporary durable storage of private resumes. Support candidate/job API architecture or a typed client data boundary, with no secrets in frontend output.
- [ ] **Project docs and distributable source.** Provide complete organized source, README with install/run/demo instructions, Supabase database/auth/storage setup, deployment instructions, `.env.example`, migrations and a source ZIP excluding secrets, private files and unnecessary build artifacts. Prepare GitHub-ready source but do not claim a repository exists until authorized and verified.
- [ ] **External deployment and repository status.** The public website must not be described as deployed until Vercel authorization and successful permanent HTTPS publication are verified. Connecting the managed project's canonical Git repository to GitHub requires its owner-confirmation workflow. If unavailable, state the exact blocker and give setup instructions rather than implying deployment or repository creation.
- [ ] **Validation evidence and delivery.** Resolve source diagnostics and available build/type errors; validate key rule-based matching and parsing logic; check route manifest and server readiness. Report verified capabilities and any unconfigured integrations explicitly. Provide requested source ZIP and documentation links when created; report external deployment only if confirmed successful.
